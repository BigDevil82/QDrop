# 已知问题与下一步

一期功能已实现，验收尚未全部完成，详见 TEST_RESULTS.md。真实部署地址由部署者保存在仓库忽略的 deploy/.env 和客户端私有设置中；没有执行远程安装或修改现有站点。

当前限制：Android 仅发送，Windows 仅接收；协议与服务端权限双向。Android 离线可向已缓存的电脑身份排队，缓存不能证明目标在线；打开 App/刷新设备更新状态。手机任务重试与缓存清理由 WorkManager 调度，Doze/强制停止可能延迟，不能保证在 TTL 秒级准时删除本地缓存。发送状态在前台刷新或队列执行时更新，没有全天后台连接。

Windows 自包含包已在本机安装运行，本机存在 Windows App Runtime 1.8，尚无干净主机验证。通知已注册并提交，通知按钮与退出后激活尚未完整手工验收。Windows 界面以 WPF code-behind 实现，尚未整理成完整 MVVM 分层。

Caddy 后 API 未信任转发头，因此 IP 注册失败限制按代理地址共享；设备级限制仍独立。单实例 SQLite 是当前设计边界。Docker 配置通过解析，但本机 daemon 未运行，容器运行、实际 ACME/TLS、备份恢复演练未执行。测试依赖有一条 Starlette/httpx 弃用警告。

两张图片同批发送已由用户确认且摘要/ACK 复核通过。此次附带文本未收到；已修复多项分享列表文本解析和手动准备文字替换文件的问题，不能确定此次具体原因。新的混合发送仍待来源入口端到端复验，不能替来源 App 保证提供文本。

下一步先完成一期缺口：混合分享复验；真实离线 5 分钟；Windows 锁屏/休眠/开机登录；磁盘满；通知按钮；干净 Windows 安装；公网 TLS、Compose 运行与备份恢复、30 次延迟测量。签名库与密码由用户安全备份，不能随源码复制。

一期验收后再讨论二期：Windows 主动发送、Android 前台接收与手动复制/打开、接收通知拒绝时降级；三期后台提示与验证码可行性另行验证。本轮没有实现这些可选客户端功能。
